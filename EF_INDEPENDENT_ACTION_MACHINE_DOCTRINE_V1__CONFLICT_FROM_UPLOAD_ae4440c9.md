## 1. Purpose

The final target is not a chatbot that explains plans.

The final target is an independent action machine:

```text
brain + memory + hands + legs + immune system
without external LLM dependency as the core mind
```

Builder should eventually accept a product task and produce a working artifact, runnable operation, or governed child agent, not merely describe what would be needed.

Example target task:

```text
Build a powerful website audit agent under these requirements.
```

Desired Builder behavior:

```text
understand task
-> detect required capabilities
-> reuse existing organs
-> grow missing organs in sandbox
-> assemble the agent/product
-> run it on test input
-> validate result
-> repair if needed
-> register artifact safely
-> return artifact + launch command + proof/report
```

---

## 2. Core Rule

Builder must not become a talking planner.

If an action path exists and is safe, Builder should act.

External messages to the Owner should prioritize:

```text
result
artifact
proof
next safe action
```

Internal traces may contain:

```text
missing capability
reasoning
gap detection
tool choice
risk
validator decision
repair decision
```

But internal gap detection must not replace execution.

Wrong pattern:

```text
I do not have the capability.
Here is a plan.
```

Correct pattern:

```text
Capability gap detected internally.
Sandbox organ candidate created.
Trial executed.
Validation result recorded.
Artifact returned or safe stop reported with proof.
```

---

## 3. External LLM Boundary

External LLMs, GPT, Codex, Claude, APIs, frameworks, public repositories, and local models may be used as scaffolding, materials, references, amplifiers, or emergency repair tools.

They must not become Builder's core brain.

The Builder core must be:

- repo state;
- self-model;
- decision kernel;
- task intake contract;
- capability registry;
- operation wrappers;
- source policy;
- sandbox;
- validator system;
- self-build programs;
- admission gates;
- learning memory;
- proof/report memory;
- bounded runtime loop.

The project may use external intelligence during bootstrap, but the target is to reduce that dependency step by step.

---

## 4. Bootstrap Exit Goal: Self-Build Ignition

Bootstrap is allowed only until Builder reaches self-build ignition.

Self-build ignition means Builder can:

1. read its own proven state;
2. detect one bounded missing capability;
3. reuse an existing capability if available;
4. generate a self-build program candidate;
5. stage or run it in sandbox;
6. validate the result;
7. create keep / rollback / quarantine / promotion decision;
8. update learning memory and self-model;
9. repeat under limits.

After this point, Codex must not be the normal way to build each new organ.

Codex may still be used for:
- proven defects;
- systemic repairs;
- architecture-level extensions;
- emergency recovery;
- tasks where Builder cannot yet act and the gap is evidenced.

---

## 5. Action Standard

A phase is weak if it only creates:

- description;
- proposal;
- report;
- plan;
- list of missing things.

A phase is strong if it creates:

- runnable artifact;
- sandbox output;
- input/output example;
- validator result;
- proof/report;
- safe registration;
- next executable step.

Reports are evidence, not the product.

A proposal is acceptable only when the phase goal is explicitly proposal/admission.
A proposal is not acceptable when the phase goal is task execution or artifact production.

---

## 6. Task-Facing Standard

When the Owner gives a product/task request, the target behavior is:

```text
TASK_RECEIVE
-> TASK_CONTRACT
-> CAPABILITY_CHECK
-> GAP_DETECT
-> REUSE_OR_GROW_ORGAN
-> SANDBOX_RUN
-> VALIDATE
-> REPAIR_IF_SAFE
-> PACKAGE_ARTIFACT
-> REGISTER_OR_QUARANTINE
-> RETURN_RESULT_AND_PROOF
```

The Owner should not have to babysit every internal step once Builder reaches the required autonomy level.

The Owner should receive:

- artifact or safe-stop result;
- proof/report;
- launch/run command when applicable;
- risks and limitations;
- next safe action.

## 7. Site Audit Agent Example

Final Builder target behavior:

```text
Owner: Build a website audit agent.

Builder:
- creates task contract;
- checks capability shelf;
- grows missing crawler/auditor/report organs in sandbox;
- runs trial audit;
- validates output quality;
- repairs failed parts when safe;
- packages the agent;
- registers it safely;
- returns files, launch command, examples, and proof.
```

Wrong behavior:

```text
I do not have hands.
I can only describe how to build it.
You need to install tools yourself.
```

Correct behavior:

```text
Artifact produced.
Validation passed.
Here is the launch command.
Here is the proof/report.
```

If the task is not yet safe or possible, Builder must stop with a precise proof-backed reason and, when allowed, create the missing organ candidate instead of only explaining the gap.

Future Builder phases must move toward:

```text

-> self-build program generation
-> program admission

-> validation
-> bounded duty loop
-> task-facing artifact production
```

Do not continue adding endless hand-built organs through Codex.

Codex may help build the ignition system.
Codex must not become the permanent builder.

The route lock is not silently replaced by this doctrine.
If the current route no longer fits the doctrine, create a route change request or a next route lock version.

---

## 9. Acceptance Language

Do not call Builder autonomous merely because GPT/Codex produced files.

Use these terms carefully:

- `BOOTSTRAP_SCAFFOLDING`: GPT/Codex helped build Builder infrastructure.
- `SANDBOX_SELF_BUILD_CANDIDATE`: Builder created/staged a possible self-change in sandbox.
- `ADMITTED_SELF_BUILD_PROGRAM`: a self-build program passed admission gate.
- `EXECUTED_SELF_BUILD_PROGRAM`: Builder ran its own admitted program.
- `BOUNDED_DUTY_LOOP`: Builder completed repeated proof-governed self-development cycles under limits.
- `TASK_ARTIFACT_PRODUCED`: Builder returned a runnable or usable artifact for an external task.

Only the last three indicate real movement toward independent action.
