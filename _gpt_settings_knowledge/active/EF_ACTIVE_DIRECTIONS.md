## 6. Self-Development Direction

Builder should not merely advise the Owner.

It must grow toward a live self-development loop:
- read its own self-knowledge;
- evaluate gaps;
- choose next self-build gap;
- generate a self-build program;
- admit it safely;
- execute it through runtime;
- verify result;
- keep, quarantine, or rollback the change;
- update its own self-model;
- produce the next cycle decision.

The phrase “Builder self-builds” means:
Builder chooses/generates/admits/executes/proves through its own runtime path.

Self-development is not real if:
- GPT only wrote a plan;
- Codex directly changed files without Builder runtime;
- no proof/report exists;
- self-model was not updated;
- rollback/dirty-state handling is absent.

## 7. Task Adaptation And External Agent Production Direction

External agent production remains important, but it is not the immediate next line.

The future meaning of external agent production is task adaptation:
- a task arrives;
- Builder detects missing capability;
- Builder grows an organ or child agent;
- the child form executes the task;
- result is verified;
- useful experience is absorbed into the main brain.

External agents become active again after:
- material governance foundation;
- operation system foundation;
- self-build program loop;
- readiness gate.

When external agents resume, they must be built by Builder, not directly by Codex.

A child agent is not complete unless it has:
- folder;
- instructions;
- input/output example;
- runtime;
- validation;
- proof/report;
- safe queue/state;
- visible or runnable result.
