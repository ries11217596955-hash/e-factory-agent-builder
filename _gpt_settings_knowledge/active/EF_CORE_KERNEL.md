## Parallel Work Rule

Builder and Codex may work in parallel only when their workspaces are separated.

Correct pattern:
```text
main repo / accepted HEAD = live Builder runtime
separate worktree or separate clone = Codex repair/build work
merge/commit/push only after validator and proof
```

Forbidden pattern:
```text
live Builder reads scripts from the same dirty repo while Codex edits those scripts
```

Reason: it mixes runtime outputs, patch files, and proof artifacts, causing false diff failures and unsafe operator confusion.

## Maximal But Bounded Rule

For foundational Builder organs, do not default to a weak "minimal" implementation.

Correct target:
```text
maximal useful layer
+ bounded scope
+ sandbox/session-local first
+ validator
+ proof/report
+ no accepted-state mutation until admission
```

"Not minimal" does not mean uncontrolled scope. It means the organ should be complete enough that the project does not immediately return to old debt.
